## === PROJECT GOAL ===
**Objective:** Build an enterprise-grade financial simulation engine (Monte Carlo) for startups and investors.
**Core Philosophy:** "Correctness over Convenience." We model non-ergodic path dependence. Simulate path-dependent volatility using specific distributions (Normal, Student's T, NRIG).
**Identity:** Username-based.

# === IMMUTABLE ===
# 虫 Master Architectural Reference: The Fortress Standard (V3.1)

**Status**: Hardened | **Date**: 2026-01-24 | **Target**: Frontend & Backend Architects
**Core Mission**: To maintain 100% mathematical integrity, structural consistency, and tenant isolation across the Evolutesix Financial Engine.

## 1. TECHNOLOGY STACK (Immutable)

The stack is selected for institutional-grade precision, type safety, and high-performance simulation execution.

* **Backend:**
    * **Language:** Rust (Edition 2021).
    * **Web Framework:** `axum` (with `tokio`).
    * **Database:** PostgreSQL via `sqlx` (Compile-time checked queries).
    * **Math:** See Immutable Data Contract below.
    * **Serialization:** `serde` / `serde_json`.

* **Frontend:**
    * **Framework:** Next.js 14+ (App Router).
    * **Language:** TypeScript.
    * **Styling:** Tailwind CSS (Utility classes).
    * **HTTP Client:** Axios (via `lib/api.ts`).
    * **Visualization:** Chart.js (`react-chartjs-2`).

### **Database & Infrastructure**
- **Database**: PostgreSQL (Strict Relational).
- **Infrastructure**: Docker and Docker-Compose for environment parity.
- **Migrations**: Managed via `sqlx` to ensure schema integrity.

---

## 2. THE "IRON LAWS" (Security & Integrity)

These rules are non-negotiable.

### A. Tenant Isolation & Security
1.  **Strict Isolation:** Every business entity (Fund, Company) MUST belong to a `tenant_id`.
2.  **Query Rule:** Every SQL `SELECT`, `UPDATE`, or `DELETE` must explicitly filter `WHERE tenant_id = $1` (derived from JWT), *unless* specifically querying `is_public_template = true` (Library Mode).
3.  **Demo Guard:** The `guard_public_templates` Database Trigger protects the `is_public_template` flag at the engine level. Only the designated Demo Admin UUID can set this to `true`.

### B. Type Safety
1.  **Money:** ALWAYS use `rust_decimal::Decimal`. NEVER use `f64` for storage/API.
2.  **Percents:** ALWAYS use `Decimal` (e.g., 5.0 = 5%).
3.  **IDs:** ALWAYS use `Uuid`.

### C. Serialization & API
1.  **String-Decimal Standard:** All Currency, Decimals, and Percentages MUST be transmitted as **Strings** (e.g., `"1250.50"`, `"3.0"`).
2.  **Solvency Arrays:** `solvent_counts` arrays (e.g., `p50_solvent_count`) are **MANDATORY** (`Vec<i32>`). They must never be `Option` or `null`.
3.  **Scoped Naming:** Fields must be scoped (e.g., `role_name`, `expense_name`) and never simply `name`.

---

## 3. The Immutable Data Contract

| **Layer** | **Type** | **Responsibility** |
| ----------------- | ---------------------------- | --------------------------------------------- |
| **Storage / API** | `rust_decimal::Decimal`      | Exactness, no rounding errors in DB.          |
| **Boundary** | `ToPrimitive::to_f64()`      | One-time conversion with overflow safety.     |
| **The Hot Path** | `f64`                        | Hardware-level speed for 1,000+ trajectories. |
| **Aggregator** | `Decimal::from_f64_retain()` | Convert results back for the API response.    |

### 潤 Unified Identity Contract
| **Entity** | **Field** | **Source of Truth** |
| ------------ | ----------- | ------------------------------------------------------ |
| **Identity** | `user_id`   | **UUID** (Stored in JWT and returned in AuthResponse)  |
| **Auth** | `sub`       | **Username** (String, used only for display)           |
| **Security** | `tenant_id` | **UUID** (The primary filter for ALL database queries) |

### The "Solvency Source of Truth"
- **New Standard:** You must exclusively use `is_solvent: boolean`.
- **Logic:** If `is_solvent === false`, the Company is dead. All financial fields (Revenue, Cash, Opex) are guaranteed to be `0.00`.

* **Backend Structure:**
    * `backend/src/handlers/` -> All API route logic.
        * `lifecycle.rs` -> **(New)** Duplicate, Move, Template Cloning.
        * `fund_simulation.rs` -> The Monte Carlo Engine endpoint.
    * `backend/src/models.rs` -> Shared Structs and DB schemas. (Reference this for column names).

    * `backend/src/engine/` -> V4 Simulation Kernel (Orchestrator).
    * `backend/migrations/` -> SQLx migration files (SQL).

---

## 5. API PATTERNS (V3.1)

### A. Lifecycle Management
* `POST /api/lifecycle/plans/:id/duplicate` -> Deep Copy Plan + Children.
* `POST /api/lifecycle/companies/:id/duplicate` -> Deep Copy Company + Plans.
* `POST /api/lifecycle/funds/:id/duplicate` -> Deep Copy Fund + Companies.
* `PUT /api/lifecycle/companies/:id/move` -> Reassign `fund_id` (Same Tenant).
* `GET /api/lifecycle/templates` -> List Public Demo Funds.
* `POST /api/lifecycle/templates/:id/clone` -> Copy Demo Fund to User Tenant.

### B. Simulation Output (SimulationResult)
* **Fan Chart:** `p[0-100]_value` (Decimal Arrays).
* **Structure:** `p[0-100]_solvent_counts` (Integer Arrays) -> **MANDATORY**.
* **Table:** `p50_data` (Object Array) -> Detailed Financials for the median run.
* **Cliff:** `survival_rate` (Decimal Array).

### C. Event Management
* `GET /api/events?target_ids=uuid1,uuid2` -> Batch retrieve events for specific targets (Plans, Funds, or Companies). Returns empty list if no IDs provided.

---

## 6. CORE ENGINE LOGIC (`backend/src/projection.rs`)
* **Mechanism:** Breadth-First Traversal (Time-step based).
* **Scope:** Handles Revenue, COGS, OpEx, Capital Injections, Dividends, Credit Facilities.
* **Monte Carlo (Company/Fund):** Runs 1000+ iterations. Calculates percentiles (P5, P50, P95).
* **Insolvency:** Logic stops simulation trajectory if `cash < -credit_limit`.

---

## 7. Simulation & Business Logic

#### 7.1 Statistical Integrity (The Anchored Median)
- **P50 Trajectory**: The "Median" line represents the fictitious path connecting the **median value of each individual month** across 1,000 simulations (Cross-Sectional).
- **Metric Alignment**: Runway, Valuation, and Net Value labels must be derived from this specific monthly median trajectory.
- **Zombie Explanation**: The "Solvent Companies" count may fluctuate (e.g., 2 -> 1 -> 2) on the P50 line because the median run in Month X might be different from the median run in Month Y. This is mathematically correct for a cross-sectional view.

#### 7.2 Fund Level Logic
- **Relative Time**: The system uses **Integers** for months (e.g., Month 1, Month 12).
- **Anniversaries**: Annual changes are applied in the anniversary month, calculated as `(m - role.start_month) / 12`.
- **Hard-Stop Insolvency**: If `is_solvent` becomes false, all flows and cash snap to `0.00`.

---

## 8. Recorded Micro-Decisions
1. **P50 Runway = "Remaining Time"**: If the median trajectory is insolvent, runway explicitly returns `0`.
2. **Retention of `valuation_name`**: Kept specific semantic naming.
3. **Staffing "Role Name"**: Scoped naming `role_name`.
4. **Transactions**: Any "Duplicate" or "Clone" action MUST use `sqlx::Transaction`.
5. **Naming**: Cloned entities append `(Copy)` to the name.
6. **Event Nomenclature**: API uses `event_name` and `event_type` exclusively, replacing legacy `shock` terminology.
